# Profile v7 on real data: a dry run (#167, D3)

Profile v7 (`ops/poc/profiles/local-real-rounds.v7.json`, artifact schema `local-experiment-artifact.v6`) grows the
pools from the sources v6 already reads, and sits beside v6: `PROFILE_VERSION` stays v6 until the data run (D4). This
dry run ran it with `pnpm prepare:poc --resume --profile=local-real-rounds.v7 --journal=dry-v7.jsonl` on a copy of the
v6 journal, in a separate worktree, to set the profile's final targets from measured yields. The dry artifact and its
pin were restored afterwards, and nothing from the run is committed but this record and the profile.

### Commit search's secondary rate limit

The plan added four to six date windows in the productive organisations and replaced django's empty one. Searching
them failed every time. GitHub answered a search page with a bare 403, "You have exceeded a secondary rate limit". The
response carried no `retry-after`, and its `x-ratelimit-remaining` was not 0 (the search limit read 24 of 30). The
transport therefore reports it as `UNSUPPORTED_STATUS 4xx`, not as a checkpoint, and discovery fails.

- The first refusal came after about ten pages sent back to back; once tripped, two pages were enough.
- Neither ten seconds between pages nor more than an hour's pause cleared it.
- A run that fails in discovery cannot resume it part way: the journal keeps search pages only from a run whose
  discovery finished, so each attempt searched every query again.

What this PR does about it:

- Live search pages are now at least ten seconds apart (`SEARCH_PAGE_SPACING` in `runtime.ts`; replayed pages and
  other requests go at once). It did not clear a limit already tripped.
- The v7 profile keeps v6's seven productive searches, all replayed from the journal, and drops django's window, which
  found nothing.

Suggested follow-ups:

- Discovery that resumes per query.
- A bare 403 on a search page treated as a checkpoint about a minute out.
- New windows tried again on another day, with their own dry run.

v6's microsoft window also found 167 commits on 21 October against 165 on 19 October, so a fresh search does not
reproduce the recorded one exactly.

## The grown decks

- **Which project?** Every language has two groups, each two answers and two decoys offered by both of its rounds.
  - No repository is offered in two groups or two languages, and every option appears in exactly two rounds.
  - JavaScript, for one: core-js and SerenityOS against uni-app and prettier, then three.js and mermaid against babel
    and parcel.
- **Which algorithm?** Each of 24 algorithms in six families is answered twice, in two languages: 21 rounds in
  Go, 21 in Python, 6 in Java.
  - The languages take turns as v6's selection does, over all ten curated pins, so Python and Go come first more often.
  - Quicksort, for one, is `MysteryRange` and `Mystery` with a `Partition` pivot in Go, and a `mystery` that splits
    around a random pivot in Python, both against heapsort, Shell sort, and merge sort.
- **Before or after?** 30 refactors from six organisations (google 9, microsoft 8, facebook 5, kubernetes 4, github
  2, vercel 2), the later pane the bigger one in 15.
