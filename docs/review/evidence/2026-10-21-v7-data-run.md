No session reached a `RATE_LIMIT_CHECKPOINT`, and discovery replayed all twelve search pages from the journal, so
GitHub's secondary search limit (#194) never came into play. Session 1 logged
`PREPARATION_JOURNAL mode=resume replayed=6016 live=5`. The five live requests were the two Stack v2 preflight reads
(the revision's access check and the dataset card), which `--resume` always makes live, and three GitHub repository
reads that the journal held as failures only an offline replay repeats. All five answered as before, so the resumed
journal holds the same 6,290 entries, with the same hashes, as the dry run's.

The dry run counted 6,152 requests to the same artifact. The difference is one retry: the dry run's final session
retried one request once (2 s), and the replay needed none.

Each session took about 40 minutes, nearly all of it CPU. A profile of the first `--offline` session (2,460 s) shows 99%
of it in selection: missing-line 1,217 s, name-function 999 s, and fix 96 s. The time goes to `revealsProtected`
(`selection.ts`), which runs for every candidate. It joins the public text of the deck's selected sources with the
candidate's, then tests each source's protected values (licence names, repositories, authors) against it. Each test is a
whole-word regular expression compiled anew (`containsProtected` in `compose.ts`), so each candidate's check grows with
the square of the deck's size. The game's parser had the same cost until D2 (#166) ruled out a value missing from the
text before compiling its pattern. The same substring test here would give the same answers and cut most of the time.

### Reading every trace

Nothing runs a round's code to check a step-through, so the first run's 30 algorithm traces were each read against the
code shown, and against the file in the journal where a helper sits outside the pane. Six were wrong, and
`ops/poc/questions/reviewed.ts` now refuses them (`REVIEW_TRACE_WRONG`, beside run 2's counting sort). A second run
then replayed the journal with no live call and published 74.

| Round | Algorithm | What the trace gets wrong |
| --- | --- | --- |
| `…16543b558b4a364ac2cba43c` | Cocktail shaker sort, Python (since v6) | its last frame has start 0 and swapped false; swapped stays true and start becomes 1 |
| `…cf96ab1e9c386c57af63b4fa` | Heapsort, Python (since v6) | the first pass leaves `[3, 1, 2]`, already a heap, not `[3, 2, 1]` |
| `…331e3b7185cf0d185048f440` | Coin change, Go | the table ends `[1, 1, 2, 2]` and the code returns 2, not 3 |
| `…31b59c08e6402da2ed2c462a` | Quicksort, Go | `Partition` pivots on the last item and returns index 1, not 2 |
| `…b8dd88f7583e2974ed3dcfb6` | Binary search, Python | with left and right both 1 the loop runs once more |
| `…bfc94bb5509bb43b7865769f` | Breadth-first search, Go | the code returns on meeting the end vertex and never takes vertex 1 off the queue |

Six of 30 is a fifth. A model writing a step-through from code it cannot run gets small inputs wrong often enough that
every trace layer needs a reader before it ships.

### What reads badly

- **A project round gives itself away** (cli/cli, `…8a81aed1`). The pane sets `"GITHUB_TOKEN"`, and the answer's
  description is "GitHub’s official command line tool".
  - The #77 word rule misses it because `wordStems` splits the description's `GitHub` at its case change into `git` and
    `hub`, but reads the pane's `GITHUB` whole as `githu`.
  - The parser's check and the leakage test's overlap solver use the same function, so neither catches it.
  - The fix is a v7 rule change and a new run, so it is left for the owner.
- **A pane in Chinese beside the only option described in Chinese** (ruoyi-vue-pro, `…b5b4e69c`). The pane is
  `@Schema(description = "管理后台 - 角色创建 Request VO")`, and only the answer's description is in Chinese. The word
  rule reads Latin letters only.
- **One idea twice in the output deck.** v6's `decimal_to_negative_base_2` (`maths/base_neg2_conversion.py`) and v7's
  `decimal_to_negative_binary` (`conversions/int_to_negative_binary_base.py`) are the same conversion to base −2. The
  inverse, `negative_binary_to_int`, is also in the deck. `sameIdea` compares words, and `binary` is not a word of
  the other name.
- **Two name-the-function rounds both answer `addEdge`,** in Go's lowest common ancestor and Java's heavy-light
  decomposition. Both panes are four lines.
- **Some missing-line pairs give away the answer with both hints.** In `graphs/a_star.py`, hint 1 says the missing line
  tests a condition. Hint 2 then pairs the answer with an assignment.
