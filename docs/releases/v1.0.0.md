# CodeGuessr v1.0.0

CodeGuessr is "GeoGuessr for code": read an excerpt of real open-source code, buy a clue if you need one, and guess
where it came from or what it does. v1.0 is the first tagged release: launch-ready, but still local (milestone #4,
checklist #130). It runs on one machine; hosting and its hardening (#97–#100) come in the next release.

## What's new since the six-deck build

The six-deck build went live on 2026-10-13 (#17). v1.0's work merged from 2026-10-14 to 2026-10-20, in #110–#162.

### Ten decks, 296 rounds

The v1.0 data run (#129, 2026-10-19) froze ten decks in one artifact, against six decks and 144 rounds before.

- **Recognise:** Which project? (24), Which language? (52, now 26 languages in 13 look-alike pairs, seven of them
  rarer: Haskell/Elm, OCaml/F#, Erlang/Prolog, Clojure/Racket, Julia/MATLAB, Ada/Pascal, Elixir/Crystal), Which
  algorithm? (24), and two new decks: **Which framework?** (32 TodoMVC files, #62) and **Which exercise?** (48
  Exercism reference solutions, #58).
- **Reason:** Before or after? (20, up from 10), Predict the output (24), Spot the fix (24), and two new decks:
  **Missing line** (24, #57) and **Name the function** (24, #73).
- New leak rules screen every v6 round: project panes that echo an option's words (#77), output answers that read off
  the call (#78), data-only, generated, and repeated rounds (#84), and before-after pane sizes and prose-only changes
  (#75). Language option sets no longer recur, and the leakage test simulates players who remember (#81, #80).
- The run journals every response, so `pnpm prepare:poc --offline` rebuilds the artifact byte for byte with no
  network. Evidence: `docs/review/evidence/2026-10-19-v6-data-run.md`.

### New ways to play

- **Mixed:** one round from each of five decks drawn at random (#56).
- **Today's five:** the same mix for everyone on a given day (#74).
- **Seeded deals:** a game's address carries its deal, so a reload shows the same game, and "Deal new rounds" moves on
  without repeating a round until the pool is spent (#40).

### Generative UI, opt-in

With `GENUI_ENABLED=1` and an OpenRouter key, each game gets one of four model-written designs (#101). Three explain a
round once it is answered, and one is a host to chat with. It runs on the Vercel AI SDK, which sends nothing by
itself.

- **The answer-lock guard** (#102) is the only path from round data to a model. Before the answer is locked, a model
  sees the deck, the prompt, the options, the hints bought, and the score, never the code. After it, the model sees the
  code and the reveal too.
- **Four designs** (#114, #115, #104):
  - **catalog:** five fixed components;
  - **composer:** the model lays out the panel from 14 checked blocks, ending in a quiz;
  - **visualizer:** a model-written page that steps through the code, in a sandboxed frame with no network and no
    access to the game;
  - **host:** a chat beside the round. Before the lock it sees no code and can offer the next hint at its usual price;
    after it, it talks about the code.
- The server checks every output before it renders. Any failure, a spent key included, leaves the static reveal, and a
  failed panel can be tried once more.
- Requests ask OpenRouter for providers that neither store nor train on prompts.

### Question layers

Generative UI inside the question, written at preparation time by a model that knows the answer, audited by a
code-blind solver, and frozen beside the artifact (#127, #128). Play never calls a model before the answer is locked.

- **Trace it** (Which algorithm?): the variables to watch, a hint in words, then a step-through of the hidden function
  on a small input.
- **Marker hunt** (Which language?): three questions to ask of the code, then hints that mark the deciding lines.

66 of the 76 rounds of those two decks carry a layer. The preparer's checks and its code-blind audit refused nine, and
a review after agent playtest run 2 refused one whose step-through was wrong. Those rounds play with their static hints.

### Four themes

Terminal, Paper, Arcade, and High contrast (#125). Every colour, font, and corner is a token; every theme passes axe's
WCAG 2 A/AA rules on real pages, and every text pair reaches 4.5:1.

### A cleaner game

The reveal puts the verdict first and folds the evidence; a five-round summary ends each game; the header is one line;
the chooser groups decks into Recognise and Reason (#126, #43, #121). Panes wrap with hanging indents on a phone, RTL
text is isolated, indents are trimmed, and Enter and shortcut keys play a round (#46, #85, #71).

The server keeps score (#96). Each game's progress is a token the server signs, and a round takes one answer. A hint's
text reaches the browser only once it is bought.

### The design experiment

Each game draws a generative design (off, catalog, composer, visualizer, host), a theme, and a question layer
independently, sealed in its session token (#106). An opt-in, anonymous event log records play with a strict schema:
no IP, user agent, chat text, or round content (#107). `pnpm experiment:report` reads it offline and compares each
factor's levels on the deal-again rate with Beta posteriors, P(best), and a pre-registered stopping rule: 506 games
per design, 475 per theme, 356 per layer level, or day 56 (#108).

### Agent playtests

`ops/playtest/` drives real browser sessions for Claude Code subagents: five Claude Haiku persona players and two
Claude Sonnet judges (#116).

Run 1 compared the four designs (`docs/review/evidence/2026-10-14-agent-playtest.md`). It found no answer leak in 41
red-team attempts, and its findings shaped what each design is shown.

Run 2 played 52 games across every deck, theme, and layer, for $0.05 of OpenRouter (#122,
`docs/review/evidence/2026-10-20-agent-playtest-run-2.md`).

- **The answer lock held:** 28 attacks on the host before the lock, and none leaked.
- **The composer is now the most accurate explainer,** with 2 wrong claims in 184, against 8 in 125 in run 1.
- **The host fixes:**
  - it is told the player's pick after the lock;
  - its planning text no longer shows;
  - a long chat keeps working.
- **Other fixes:**
  - the paste check reads hex, rot13, and reversed code;
  - a failed panel can be tried again;
  - marked lines are named for screen readers;
  - a wrong step-through was refused.

## Upgrading

- The artifact's schema is `local-experiment-artifact.v5` from profile `local-real-rounds.v6`; the parser still reads
  v5 artifacts from profile v5.
- Question layers bind to the artifact's hash, so a new artifact needs a new `pnpm prepare:questions` run.
- Generative UI stays opt-in (`GENUI_ENABLED=1` with an OpenRouter key from `~/.config/openrouter/key`); without it the
  game makes no network request.

## Known limits

- Localhost only, with no public players.
- "Spot the vulnerable line" (#59) is built but deferred, and "Which era?" (#60) is not built.
- Question layers cover two decks. The other four designs (#128) come later.
- The experiment has no real players yet; the report waits for its targets.
- **Explainers run on Claude Haiku 5.5 and still make mistakes.** In run 2, the judge found between 1 claim in 100 wrong
  (the composer) and 7 (the host). Whether Sonnet does better is #120.
- **Nothing runs a round's code to check a step-through.** A reader's review refuses a wrong one, and a mechanical check
  is #159.
- **Trace it's "What to watch" list makes Which algorithm? easier to guess without reading the code** (#160). The names
  it lists are the code's own.
- Small UI polish from run 2 is #161.
- The event log is JSON lines until the toolchain moves to Node 24, which has `node:sqlite` (#21).
